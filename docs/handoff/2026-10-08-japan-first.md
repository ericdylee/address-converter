# 인수인계: 일본 주소 변환을 1급 기능으로 (방향 A)

> 새 세션은 이 문서부터 읽고 시작한다. 결정은 이미 끝났고, 남은 건 **설계 세부 확정 → 구현**이다.
> 작성일 2026-10-08. 사용자는 비개발자라 매 단계 쉬운 설명을 붙인다.

## 1. 왜 이걸 하나 (결정 근거)

- AdSense "가치가 별로 없는 콘텐츠" **5회 거절** (6/25·7/14·8/24·9/18·10월).
  4번 동안 한글 주소 가이드 글을 다듬었지만 판정이 한 번도 안 바뀜 → 글 품질 문제가 아님.
- 진단: 한글→영문 변환은 행안부 juso.go.kr이 이미 무료로 함 → 심사자·구글 모두 "재탕"으로 봄.
  반면 **일본 주소→영문은 한국어로 제대로 해주는 곳이 없음** (경쟁자 JuDress는 일본어 UI).
  한국 블로그들이 "이 일본 사이트 써라"고 링크하는 구조.
- 서치콘솔 6개월 (2026-10 기준):
  - 국가: 한국 266클릭 / 10,992노출 (97%). 기기: 데스크톱 63%, 모바일 36%.
  - 검색어 1·2위: `일본주소 영문변환` 32클릭/363노출, `일본 주소 영문 변환` 27/256 (CTR 9~12% = 이미 1페이지).
    그 외 `일본주소 영어로`, `일본 주소 변환`, `일본 영문주소`, `일본 주소 영어로 변환`. 한글주소 변환 검색어는 상위에 **없음**.
  - 페이지: 홈 `/` 141클릭/2,258노출 (일본 검색어가 여기로 옴), `/guide/korea-region-names` 77/**6,621 (CTR 1.2%)**,
    overseas-shopping 28/1,315, international-shipping 17/751, `/guide/japan-address` 3/360.
- 웹 조사로 본 사용 상황 (한국에 있는 사람이 PC로 양식 채우는 중):
  1. **비짓재팬웹·입국신고서** 숙소 주소 (가장 큰 시장 — 블로그 다수가 "호텔 측에 우편번호 받아두라"고 안내할 정도로 우편번호를 모르는 사람이 많음)
  2. **우체국 EMS 스마트접수**로 일본에 보낼 때 받는 사람 주소
  3. **일본 배대지 주소**를 해외 사이트 City/State 칸에 나눠 넣기 (디시 일어갤 질문글)

**목표는 "애드센스 승인"이 아니라 "일본 주소 영문변환 = 이 사이트"다.** 트래픽이 늘면 승인은 따라온다.

## 2. 범위 (하는 것 / 안 하는 것)

하는 것 — 기존 홈 안에서 일본 기능 강화 (새 `/japan` 페이지 **만들지 않음**: 홈이 이미 그 검색어로 상위 노출 중이라 순위 분산 위험):

1. **붙여넣기 입력** — 일본어 주소 통째로 넣으면 해석
2. **홈의 일본 존재감** — 첫 화면·제목·탭 순서
3. **결과 화면의 용도별 칸 매핑** — 비짓재팬웹 / 우체국 EMS / 해외 쇼핑몰
4. **korea-region-names 제목·설명 개선** — 노출 6,621에 CTR 1.2%, 가장 싼 이득

안 하는 것: 한국 주소 기능 제거(검색 유입 있음), 새 가이드 글 대량 작성, 외부 API 추가, 새 의존성.

## 3. 현재 코드 상태 (확인 완료)

- `lib/jp-postal.ts` — `lookupPostalCode(zip)` 만 있음. `normalizeZip`, `formatZip` 공개.
  데이터 `data/jp-postal.json` (11.5MB): `{ "1000005": [[prefEn, cityEn, townEn, prefKanji, cityKanji, townKanji], ...] }`
  우편번호 120,642개 / 행 124,423개. 런타임에 fs로 읽어 모듈 캐시.
  `next.config.ts`의 `outputFileTracingIncludes`에 `/api/jp-address` 경로로만 포함됨 → **새 API 경로를 만들면 여기도 추가해야 배포에서 파일을 찾는다.**
- `app/api/jp-address/route.ts` — `?zip=` 만 받음.
- `components/JpAddressSearch.tsx` (303줄) — 우편번호 칸 + 번지(block) 칸 2개. debounce/AbortController/키보드 네비/sessionStorage 복원.
  `onSelect(result, block)` → `app/page.tsx`의 `handleJpSelect`가 `/result?...&country=jp`로 이동.
- `app/page.tsx` — `useState<Tab>("kr")`: **기본 탭이 한국**. H1 "한글·일본 주소...".
- `app/result/FieldMappingGuide.tsx` — 서버 컴포넌트(크롤러용 본문). `JP_ROWS`에 해외 양식 칸 ↔ 필드 매핑이 이미 있음 → 용도별 매핑은 여기를 확장.
- 알려진 데이터 한계: 건물 단위 우편번호는 town이 이상하게 로마자화됨 (예: `Toranomon Kamiyachotorasutotawa` = 虎ノ門神谷町トラストタワー). 입력 해석 시 참고.

## 4. 설계안 (새 세션에서 사용자 승인 받을 것)

### 4-1. 붙여넣기 해석 — `lib/jp-parse.ts` (신규, 순수 함수 + 테스트)

입력 예: `〒150-0001 東京都渋谷区神宮前1-2-3 〇〇ビル5F`

1. 우편번호 추출: `/〒?\s*(\d{3})[-‐−ー]?(\d{4})/` (전각 숫자는 먼저 반각 변환)
2. 우편번호 있음 → `lookupPostalCode` 후보 중 `pref+city+town` 한자가 입력 앞부분과 가장 길게 일치하는 행 선택 → 그 뒤 나머지가 번지·건물(block)
3. 우편번호 없음 → 한자 역검색: 데이터에서 `prefKanji+cityKanji+townKanji`가 입력의 접두사인 행 중 가장 긴 것.
   12만 행 선형 탐색은 요청당 수 ms라 OK. (ponytail: 느리면 pref별 인덱스)
4. 못 찾으면 → 지금처럼 우편번호 입력으로 안내 (실패해도 막다른 길 없음)

- block의 번지 정규화: `1丁目2番3号` / `１－２－３` → `1-2-3`. 건물명(가타카나/한자)은 **번역하지 않고 그대로 두고** "건물명은 영문 표기가 공식으로 정해져 있지 않아요" 안내 — 틀린 로마자를 만드는 것보다 정직함.
- 테스트(`lib/jp-parse.test.ts`): 우편번호 有/無, 전각, 丁目番号, 건물명 포함, 해석 실패 케이스.

### 4-2. 입력 UI — `JpAddressSearch` 확장

- 기존 우편번호 칸 위에 **"일본어 주소 붙여넣기"** 큰 입력 1개를 주 입력으로. 기존 2칸 방식은 "우편번호로 찾기"로 보조 유지.
- API: 기존 `/api/jp-address`에 `?q=` 추가 (경로 하나 유지 → `outputFileTracingIncludes` 수정 불필요). 결과는 기존 `JpAddressResult` + block.

### 4-3. 홈 첫인상

- 탭 순서/기본 탭: 일본을 기본으로 할지 **사용자 결정 필요** (한국 유입도 홈으로 옴 — 141클릭 중 일부). 대안: 기본 탭은 그대로 두고 URL `?tab=jp` 지원 + H1·설명에서 일본을 앞에.
- H1/메타 description에 실제 검색어 반영: "일본 주소 영문 변환", "비짓재팬웹·EMS".
- **메타 제목 변경은 기존 순위에 영향 가능** → 검색어 문구를 넣는 방향으로만, 크게 갈아엎지 않기.

### 4-4. 결과 화면 용도별 매핑 — `FieldMappingGuide` 확장 (서버 컴포넌트 유지)

일본 결과에서 탭/섹션 3개: **해외 쇼핑몰 (기존 JP_ROWS)** / **비짓재팬웹** / **우체국 EMS 스마트접수**.
⚠️ 비짓재팬웹·EMS의 실제 칸 이름은 **직접 확인한 것만** 적는다 (`lib/guides.ts` 원칙과 동일 — 확인 안 한 칸 이름 지어내지 않기).
확인 방법: 공식 화면/공식 안내 페이지(services.digital.go.jp, ems.epost.go.kr). 확인 못 하면 그 섹션은 빼고 진행.

### 4-5. korea-region-names CTR

`app/guide/korea-region-names/page.tsx`의 metadata title/description, `lib/guides.ts` 해당 항목.
노출 많은 검색어(`province 서울` 등)에 답이 제목에서 바로 보이게. 본문은 건드리지 않음. `verified.date`는 실제 재확인 안 했으면 올리지 않음.
